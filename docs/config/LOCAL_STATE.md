# 本地工作状态

开发环境使用 `src-tauri/resources/state.toml` 保存 DP 工具路径、各页面参数路径、图片目录、当前图片和页面等轻量状态，与其他可维护 TOML 配置放在同一目录。发布版使用程序旁的 `resources/state.toml`；目录不可写时回退到用户配置目录。

首次启动按以下顺序读取：`src-tauri/resources/state.toml`、旧项目根目录 `resources/state.toml`、用户配置目录的状态。迁移保留旧文件作为备份；开发目录不可写时直接使用用户配置目录，不继续写旧位置。损坏的状态文件不会被默认值覆盖。应用先通过 `src/services/restoreMtkFiles.ts` 检查历史导入文件，再恢复MTK状态并显示路径：覆盖 `cpp_paths` 的全部ISP/标签、独立CA-LTM、旧版 `cpp_path` 和 `debug_parser_path`，相同文件只检查一次。确认不存在或空白的文件路径从恢复状态剔除，卡片回到未导入状态，提示和复制入口也不会残留失效路径；清理后的MTK设置经既有 `saveStateSection` 队列保存。检查IPC异常时保留未能确认的记录，解析失败但文件存在时也保留路径供手动重试。图片目录/当前图片不在此次文件清理范围内，仍按原流程恢复和扫描。DP工具只检查，不会自动执行，可使用重命名的 `.exe` 文件，选择后立即等待状态落盘。旧状态若没有 `debug_parser_path`，需要重新选择工具一次。

状态包含本机路径，已加入 Git 忽略，也不在打包资源清单内。分栏比例会保存小数，旧状态中的整数比例仍可读取。`src-tauri/.taurignore` 排除状态和临时文件，避免保存触发开发应用重启。请退出应用后再手动编辑。

进入MTK后会恢复启动检查通过的全部参数路径，包含独立的 `ISP6S|CA-LTM`。同一路径加载成功或失败的结果在本次进程会话中复用，切到首页再返回不会重复检查或弹出相同失败提示；尚未完成的加载仍可恢复。通过启动校验后又失效的路径或解析失败可手动重新选择文件重试，下次启动继续检查。提示框中的完整路径自动换行，不超出边框或视口。启动校验不会删除任何用户文件。

支持多开：重复启动程序会打开独立进程。各进程启动时读取共用的 `state.toml`，运行期间的图片选择、参数导入和界面状态分别维护，不自动同步。保存时使用独立临时文件再原子替换，最终配置由最后一次完成的保存决定（整个状态快照），其他实例保存的配置可能被较早启动实例的快照覆盖。图片缓存和参数草稿临时文件按进程隔离；托盘退出或重启只作用于对应实例。全局快捷键由成功注册的实例响应，其他实例遇到占用时跳过注册。

开发验证命令（在项目根目录运行）：

| 命令 | 验证内容 |
| --- | --- |
| `npm run typecheck` | 前端类型检查 |
| `node --test scripts/workspace-persistence.test.mjs` | 选图、参数路径、保存队列和失败恢复 |
| GitHub Actions `cargo test --locked --manifest-path src-tauri/Cargo.toml` | 临时目录下的迁移优先级、回退、连续保存和重新加载 |
| 手动迁移验收 | 仅在用户明确安排的桌面验收环境运行；核对当前本地状态字段一致性并保留旧文件 |

界面验收：使用 GitHub Actions 生成的 Windows x64 产物，选择 DP 工具、AE/ToneMap 参数文件和图片目录，切换到非首张图片，再正常退出并重新启动。核对路径、页面、选中图片及按需解析结果；也可通过设置打开实际状态目录。无桌面交互的自动测试仅验证状态与 IPC 边界，不代表已完成界面重启验收。
