# MTK JPEG 私有 EXIF：直接读取与手动兜底

## 使用行为

1. **导入时一次准备，普通切图只读 TOML。** 新 `prepare_image_metadata` 按图片顺序读取 JPEG 的 MTK APP5/APP6/APP7 私有数据、比较已有 TOML，并在导入目录保存同名 TOML。整个目录准备完成后才发布索引；首次导入使用逐图片进度，不在每次点击时重复解析 JPEG。`MtkView.tsx` 的手动导入与启动恢复都走 `prepareWorkspaceImageDirectory`，切换 AE Basic / ToneMap 或离开页面不会丢失任务收尾。
2. **已有 TOML 先比较，不以条目总数决定覆盖。** JPEG 结果必须覆盖已有有效字段身份、标量/重复数组类型与长度、完整统计块名称及形状，且严格新增至少一个字段/重复项/统计块，才以 JPEG 为权威更新原文件。等量、缺少原有字段、含未知节/不可比较数据时保留已有内容；损坏、超限或不可读的原 TOML 不当作空文件覆盖。已知模块别名及根级 AE_TAG 等明确前缀可安全归一化，未知节不猜测；AE_DISPLAY / Detail / 来源元信息不形成“更全面”的优势。
3. **统一保存真实的完整性状态。** 可读的部分结果也保存，但 `[__luxe_exif].needs_fallback = true` 不可清除。普通 JPEG/PNG 没有私有 EXIF 时，可以生成仅含诊断/待兜底状态的 TOML，避免切图反复尝试相同 JPEG；它不是成功解析、空矩阵或零值字段。目录准备返回新建、升级、保留、复用、无数据、失败与部分数量。
4. **重复导入复用已验证准备结果。** `[__luxe_exif.preparation]` 保存图片路径/大小/mtime、内容与诊断指纹，以及解码器/头文件库版本签名。同图同内容命中时不重新解析 JPEG、不反复重写 TOML；图片、TOML 业务/诊断或解码器/资源变化会重新对账。`build.rs` 对实际枚举与相关 Rust 源码生成签名，不让缓存的未知版本在增加 `.h` 后永久失效锁死。
5. **DebugParser 最后兜底。** 手动按钮会纳入已有 `needs_fallback=true` 的 TOML，不因文件存在而跳过，也不为它重新读取 JPEG。读取已有 `.jpg.exif` 或复制必要图片到临时目录执行 DebugParser；按旧值优先补充缺失字段、重复数组尾部和完整统计块，保留已选 JPEG 字段值。只有有效内容增加才原子更新，空输出/仅改诊断不能伪装补全或阻断后续重试。

不新增设置或 capability 权限；准备/解析/清理共用 EXIF 单任务队列，普通 TOML 读取继续受最多 2 个 IPC 任务限制。`ImageEntry.toml_path`、AE/ISP 关键字与工作区身份保持不变。UI 的字段、批量字段、分组和详情命令使用严格的 prepared TOML 投影：写出失败、文件被删除或未准备时返回空/失败，而不是静默重读 JPEG。底层兼容的显式直读函数仅保留给原有测试/工具，不是普通切图链路。

## 详情页标签与数据来源

AE Basic 和 ToneMap 的详情面板共用 `ExifTable.tsx`：

- 外层详情标签在 AE Basic 中为 `EXIF / Normal / Face / LCE / bcompare`，ToneMap 中为 `EXIF / LCE / Tone.cpp`；仅调整排列，不迁移原有标签 ID、默认选择或滚动会话。
- 内层模块按 AE、AE_Table、AF、AWB、Sensor、Shading、Strobe、ISP、MFNR、N3D、SWNR、BMDN、Common、String、Detail 顺序排列；**仅实际含字段的分组生成模块标签，AE_Table 仅在有完整有效统计块时显示，Detail 始终可访问**。仅匹配头文件/识别版本、未支持或解码为空的模块只保留诊断行，不生成空标签。AE_DISPLAY 合并到 AE；DebugParser 的 ISP_HW_*、MF、CMN、RESVA/RESVB 等节归入对应模块，字段仍保留原始节名前缀。
- 搜索栏内置在模块标签上方，使用无外框白底输入、轻品牌色标签背景与交替浅底行，颜色均取 Fluent 语义令牌，随深浅主题变化。搜索采用正则表达式，仅过滤内容，不移除模块导航；保留历史、收藏和单元格复制。普通字段表保持可见行虚拟化，列标题以无障碍隐藏文本保留，不再单独占用一行。
- `AE_Table` 使用等宽数字矩阵，提供单块/全部统计选择、原始数字复制、横向滚动和 Shift + 滚轮；不创建像素图、Canvas 或直方图图形。直方图的 16 列是数值排版，不是空间网格。缺失或截短数据不补成看似有效的零矩阵。
- `Detail` 显示模块、精确头文件、匹配状态、原始版本字、签名与解码结果，共六列，不再显示“识别来源”列。后台仍保留识别来源契约用于兼容已有导出；头文件已匹配不等于其二进制布局已经解码。
- 来源区仅在 Detail 显示，路径仍在徽标的鼠标悬浮提示中。普通点击的当前读取方式是 TOML，并分别标识其内容由 JPEG 直读生成、DebugParser 兜底或未知工具生成；另显示**首次可用来源、最新内容来源与保留/更新原因**。首次来源不随后续选择覆盖；既有文件缺少历史记录时，仅记录本次首次可确认来源，不伪造历史。当前“读 TOML”与内容最初来自 JPEG 是不同维度，也不会为了标识来源再次解析图片。
- 本次之后生成的 TOML 在保留原字段的同时写入版本化的 `[__luxe_exif]` 来源元信息。该保留节与结构化 `AE_Table` 不进入图片列表的扁平关键字命名空间，避免 `parser`、`rows`、`values` 等通用叶名干扰原有字段。DebugParser 的 `[AE_Table]` 中 `<<块名>>` 和纯数字行按统计布局保存，不再被普通 `TAG:value` 提取器丢弃。

## 右键清理与读取进度

- 图片列表的 EXIF 图标保留左键“补全/导出”；右键菜单可选“清除当前图片”或“清除已选图片”的同名 TOML / EXIF。范围为明确选定图片，不会默认清空整个目录。
- 清理先调用只读的 `list_image_sidecars` 展示具体绝对文件路径，再通过 Fluent 确认对话框执行 `clear_image_sidecars`。取消不调用删除。仅允许确认清单内、同一目录、属于该图片的 `<stem>.toml`、`<stem>.exif` 和 `<image-filename>.exif`；图片不删、未确认的新出现文件不删、同 stem 多图片等归属歧义不猜测。手动修改过的 TOML 也会删除，确认框明确提示不可撤销。
- EXIF 写出与清理共用后台单任务队列，前端清理/解析互斥；删除结果分别报告成功与失败。无论成功或部分失败均清理后端缓存并刷新仍匹配的工作区，保留用户完成时的图片选择，递增 `metadataRevision` 使列表、热力图和详情按新来源重读。确认后、执行请求前若数据集已变更则拒绝删除；请求已发出后允许完成已确认的操作，但其结果不能覆盖新工作区。
- 清理后会重新执行目录准备：已确认删除的缓存重新从 JPEG 建立，其余未变文件命中准备签名；对话框明确提示会重建 TOML。删除请求范围仍仅限确认文件，重建不是扩大删除范围。
- `MetadataProgress.tsx` 只用于目录准备和手动 EXIF/DebugParser 任务。导入进度按实际已处理图片数推进，包含复用/失败，不是字节百分比或耗时预测；排队显示不确定进度。普通点击/切换 EXIF 标签只读准备后的 TOML，不再创建进度 Channel 或显示反复出现的读取进度条。
- 准备状态、进度和摘要放在同一 `imageDir` 瞬时状态中，回调校验目录、加载代次与任务仍有效；完成、失败和离开页面后，迟到消息不会重新打开进度或覆盖新数据集。不在前端驻留整目录完整 EXIF，批量字段仍只读取需要的键。

## 支持边界

实现参考 IPEParser 当前的 `mtk_3a_tool/mtk_3a_viewer.py`、`docs/mtk-exif.md` 与 `EXIF/` 枚举资源；旧 `MTK_3A_EXIF_Extraction_Guide.md` 已从参考项目删除，不再当作当前条件枚举和资源路径的依据。JPEG 直读运行时不依赖 IPEParser 目录、Python、Pillow、DP DLL 或额外子进程；手动兜底仍由用户配置的 DebugParser 提供。

| 模块 | 内置读取 |
| --- | --- |
| AE、Strobe、Shading | APP6 中有界定位的分片 KV；在已确认跨度补扫孤立记录 |
| AF | 图片目录版本 + APP6 稀疏记录；同一标签的重复数值以数组保留，数组内顺序不去重 |
| AWB、ISP | 第 6 代顺序小端 u32；第 5 代 APP7 KV |
| Common | APP5 稀疏 KV，遇到下一模块的 index-0 头停止 |
| MFNR | 第 5 代 APP5 稀疏 KV；第 6 代保留 DP 兜底 |
| Sensor、N3D、SWNR、BMDN | 识别指南中已知目录签名后标记需要兜底，不伪造字段 |

当前内置 **353 份第 5/6 代精确头文件**（13 个模块目录，共 22,037,931 字节，约 21.02 MiB），包含从当前 IPEParser 导入的规范资源及保留的 Samsung ISP 专用变体。`build.rs` 自动枚举规范命名的 `.h` / `.ha`，不再手工登记 18 个版本；添加资源后由 CI 重建并嵌入应用，运行时不读取外部 IPEParser 路径。资源预算为最多 512 文件、单文件 512 KiB、总量 32 MiB；不导入第 2/3/4 代、通用 MODULE.h 或 ISP_REG_CUSTOM 配置。Tauri 的 `bundle.resources` 不再单独复制头文件库，避免在可执行文件之外重复部署这份约 22 MB 的原始数据；仓库头文件仍保留供 CI 嵌入和测试。实际安装包体积变化等待 CI 产物确认。

资源存在不等于均可解码：资源审计明确保留并拒绝 13 份存在重复索引/无效声明的上游头文件；Detail 显示缺失、歧义、无效头文件或仅识别版本，不静默移位或改选其他版本。Node 资源审计不替代 Rust 枚举解析测试，后者仍等待 CI。支持边界如下，而非对任意 MTK 固件的兼容承诺：

- 版本由 APP6 代际魔数、图片目录版本和模块签名决定；不选本地“最高版本”。
- Samsung 与 M149 的同名 `ISP_6_10_2.h` 以签名区分；支持统一头文件中的 `MTK_EXIF_SIGNATURE ==/!=` 条件分支，并保留旧签名专用变体的精确优先级。缺少明确身份时不猜变体。
- 枚举按受限数据语法解析：注释、显式/隐式索引、前序枚举引用、括号和有界整数/位运算；单头最多 65,536 token，索引范围小于 16,384，表达式最多 128 token、嵌套深度 32，签名条件嵌套最多 16。只支持 include guard 与签名条件，不执行 C、include 或任意宏；非 guard 宏、未知指令、重复索引与越界会拒绝该模块，而不是猜值。
- 目录版本记录不能当作真实字段块。通过边界和 `4 + 32×记录数` 对齐校验的目录长度优先使用，不因首个模块含连续零值而扩大；无有效长度时才使用有界模块数量/保留字回扫。
- 第 6 代 AWB/ISP 数组必须容纳精确枚举的全部数值；目录记录按原始序号绑定自身 APP 段中的 payload，数组只在所属容器内定位，不能借用其他模块中恰好相同的版本数值。空容器保留原始槽位；无效的多容器偏移表不退化为整段扫描，单容器单声明旧布局保留兼容。截短或边界不明的数组即使同图 AE 正常也保留 `needs_fallback`；导入缓存可保存已支持字段，但不能宣称该图片完整。
- 已声明的 AF/Common/MFNR 解码为空时保留 `needs_fallback`；AF 的版本与首个 key 后必须有完整数值记录，不能仅凭截断锚点把该模块判为成功。其他可确认字段可保存为带未补全标志的 TOML，不得因该文件已存在阻断后续 DP 重试。
- 重复模块声明（含同版本重复）和多个同 marker 的 index-0 数据块不被混合命名；受影响模块停止直接解码，其余可确认的字段仍可用。KV 块版本须与选中枚举一致，后续 index-0 头不是分片延续。
- 任意 APP5/6/7 中的未知目录声明都保留兜底资格；新签名只允许在其有效所属块内，按精确版本、块头/枚举索引与完整布局唯一推断模块，后台识别来源保留为 `directory_layout`（UI 已移除该列）。无法唯一归属时不猜模块或枚举；同 marker 的搜索不能跨 APP 段或串入下一个 APP5 模块。
- 保留项目已有的 AE/ISP 关键字链路，新增私有统计与诊断，不移植参考工具的图片预览或标准 EXIF 摘要。标准 ISO 与 AE 实时 ISO 不被混写。
- AF 的 TOML 按标签保存重复值数组，不提供跨标签的完整时间线查看器。
- 同一 stem 的 JPG/JPEG/PNG 无法通过逻辑 TOML 路径唯一定位时，直接读取和导出拒绝猜测；已存在的 TOML 仍按原兼容规则读取。

## AE_Table 布局边界

统计矩阵与普通枚举标签分别解析，不从标签数推算网格大小：

| 布局 | 读取与输出边界 |
| --- | --- |
| 第 6 代 type8 | APP6 中有界定位统计记录；连续读取两份 5×5、五份 15×15 的 u16 小端网格，以及 Central_Y / Full_Y / Full_RGB 三份 1024-bin **u24** 小端直方图。需有完整字节范围、有效网格变化及 Full_RGB/Full_Y 总量一致性；不得把 u24 当 u32。 |
| 第 6 代 type10 revision 1 | 有效 offset 范围内校验 `0x0001000A` 记录与 `(64,48,8,6)` 布局；四通道各保留 256 个 u16，仅取前 48 个为 **6 行 × 8 列**。后接三份 256-bin u32 直方图；不把布局标记 64×48 当实际输出网格。 |
| 第 5 代 AE 标签重建 | 从精确枚举对应的 AE 标签还原 5×5、15×15 RGBY/OverCnt 和四份 128-bin HIST；RGBY 按同一个 u32 的四个字节拆分。枚举未声明的 bin 才允许填 0；已声明却缺失的数据不能伪造为完整矩阵。 |
| DebugParser TOML | `[AE_Table]` 的 `<<块名>>` 加纯数字行转为带 `rows` / `columns` / `values` 的子表；保留第 5 代含空格的块名。导入时按同一覆盖规则比较统计内容；普通切图不另从图片补入。截短和形状不一致的数组不展示。 |

这些是已实现布局的约束，不是本次真实 JPEG / DebugParser 逐字段对照结果。未知修订或未确认布局仍需兜底。

## 性能与内存边界

- JPEG 使用 64 KiB 缓冲读取，在 SOS/EOI 停止；元数据累计上限 **16 MiB**。不读取完整压缩像素流，不进行像素解码、缩略图生成、Canvas 或 Blob 分配。
- TOML/EXIF 文本读取同样有 **16 MiB** 上限；损坏段长度、截断文件与非 JPEG 返回明确失败，不无限扫描。
- 全字段和按键缓存复用原 `TOML_CACHE` / `TOML_FIELD_CACHE`：上限分别为 **96 项且估算有效载荷不超过 16 MiB**、**512 项且不超过 8 MiB**，按 LRU 淘汰；大于单个预算的条目不驻留。
- 批量字段请求只向前端返回所需键；当前图片已在全字段缓存时，直接抽取字段，不再次解析其 JPEG。列表不保留整目录的完整 EXIF 对象。
- 元数据 IPC 最多 2 个任务并发，手动 EXIF 批任务最多 1 个；每批逐张处理。头文件文本引用编译内不可变字符串；仅为本次图片解析需要的枚举向量，结束即释放，不建立随版本/签名不断增长的枚举缓存，也不缓存图片字节。详情模块诊断最多 256 行；超出预算保留兜底资格。
- 原 `clear_memory_caches()` / `trimMemory(true)` 会清除两类缓存并递增代次，旧任务不能重新填入已清理缓存。缓存锁不跨文件读取或解析。
- 手动 DP 仅复制需要兜底的图片；临时目录以进程和时间隔离并通过 RAII 清理。TOML 在目标目录写临时文件后 rename，失败清理临时文件。
- `src/services/imageExifService.ts` 统一导入准备及完成后的共享目录刷新，任务不会因 AE Basic/ToneMap 切页卸载而丢失收尾；同一工作区的导入/清理/解析互斥，各类进行中任务最多 16 个且结束即移除，不缓存完成结果。磁盘 TOML 是受签名校验的持久缓存，内存仅使用原有预算与当前详情文档。
- 刷新保留用户**完成时**的选择。临时 `metadataRevision` 使两页的会话缓存、图片列表和打开着的 EXIF 详情同时失效；实际文件加载用独立 `loadRevision`，不被配对选中同一路径的意图错误取消。目录换代、真实 A→B→A 加载及卸载后的局部结果不能覆盖新工作区。
- `loadImageTomlFieldsBatchShared` 必须接收 `{ entries, revision }`：仅在同一索引对象与内容代次内复用进行中的字段请求，成功/失败后均释放槽位，弱引用索引不保留完成结果。列表可见行、预取、分类、排序、Apply 与 AE/ToneMap 热力图均使用同一身份；原生 JPEG→TOML 切换后，不因路径和键相同复用旧请求。列表提交/卸载时同步隔离旧代次，每个代次独立拥有 loading 集合，旧请求的成功、失败及 `finally` 都不能污染新缓存或清除新请求标记。

这些是实现预算，不是实际进程内存或 CPU 降幅。真实性能需按 `docs/performance/MEMORY_RECOVERY.md` 对相同构建、同一数据集分别采样宿主、WebView2 browser、renderer、GPU。

## 验证与后续扩展
