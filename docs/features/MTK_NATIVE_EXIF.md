# MTK JPEG 私有 EXIF：直接读取与手动兜底

## 使用行为

1. **自动导入优先 TOML。** `prepare_image_metadata` 首先读取、验证同名 TOML 与其中的来源标记。合法已有 TOML（包括无标记的旧文件、只读文件、空文件与待兜底文件）直接复用，原字节和来源不变；不再为它读取 JPEG、核验旧准备指纹或重写元信息。损坏/超限/不安全的已有文件明确失败，不当作空文件覆盖。只有没有 TOML 时才读取 MTK JPEG 并生成同名 TOML。
2. **右键为 JPEG 直接重读并强制覆盖，不再比较合并。** 按钮直接调用 `replace_image_metadata` 处理当前目录全部图片，不打开菜单或要求第二次点击；底层仍支持显式路径列表（空列表表示全部）。有可用 native 字段或有效统计块时，以本次 JPEG 结果完整替换已有 TOML，旧字段、AF 数组、统计块、手改值与旧来源均不继承；不解析旧业务 TOML、不判断哪份更全面，成功标记 `parser=native, content_mode=native`。无可用新内容、非 JPEG、读取/写入失败时保留已有文件，不用空结果清除旧内容；摘要明确提示无数据需 DP/失败。有效 partial 可以覆盖，但必须保留 `needs_fallback=true`。
3. **左键为 DebugParser 新解析结果直接覆盖。** 用户确认当前目录后，`parse_debug_parser_directory` 强制运行配置的工具：只复制通过预检的图片到新的空临时目录，读取本次生成的 `.jpg.exif` 并转换 TOML；不先调用 JPEG 解码，也不借用用户目录中旧 EXIF。成功时只保留 DP 新业务内容，直接替换原 TOML 并标记 `parser=debug_parser, content_mode=replace`；失败/空输出保留原文件。无配置时明确提示，不暗中改成 native 或旧文本兜底。
4. **真实保存缺失/未支持状态。** 没有可识别私有 EXIF 时保存 `content_mode=metadata_only, needs_fallback=true`，后续自动导入直接读取该 TOML，Detail 显示需 DP 兜底；可读 partial 同样保存真实未补全标志，不伪造字段或零矩阵。想在新增头文件后复查旧图片，使用右键主动重读覆盖，不再因解码器版本变化自动重读所有已有 TOML。
5. **TOML 是统一持久缓存，不生成新指纹或首次/最新历史。** 自动导入/启动恢复都走共享准备服务，最多两个工作线程逐图处理，不驻留整目录完整文档；任务完成后发布索引，切页不丢收尾。旧 schema-1 的 `preparation` 仅兼容读取，Detail 不展示首次/最新。普通切图只读 TOML，不再隐式解码 JPEG。

不新增设置或 capability 权限；自动准备、JPEG 覆盖与 DP 覆盖共用 EXIF 单任务队列，普通 TOML 读取继续受最多 2 个 IPC 任务限制。`ImageEntry.toml_path`、AE/ISP 关键字与工作区身份保持不变。UI 的字段、批量字段、分组和详情命令使用严格的 prepared TOML 投影：写出失败、文件被删除或未准备时返回空/失败，而不是静默重读 JPEG。底层兼容的显式直读函数仅保留给原有测试/工具，不是普通切图链路。

## 详情页标签与数据来源

AE Basic 和 ToneMap 的详情面板共用 `ExifTable.tsx`：

- 外层详情标签在 AE Basic 中为 `EXIF / Normal / Face / LCE / bcompare`，ToneMap 中为 `EXIF / LCE / Tone.cpp`；仅调整排列，不迁移原有标签 ID、默认选择或滚动会话。
- 内层模块按 AE、AE_Table、AF、AWB、Sensor、Shading、Strobe、ISP、MFNR、N3D、SWNR、BMDN、Common、String、Detail 顺序排列；**仅实际含字段的分组生成模块标签，AE_Table 仅在有完整有效统计块时显示，Detail 始终可访问**。仅匹配头文件/识别版本、未支持或解码为空的模块只保留诊断行，不生成空标签。AE_DISPLAY 合并到 AE；DebugParser 的 ISP_HW_*、MF、CMN、RESVA/RESVB 等节归入对应模块，字段仍保留原始节名前缀。
- 搜索栏内置在模块标签上方，使用无外框白底输入、轻品牌色标签背景与交替浅底行，颜色均取 Fluent 语义令牌，随深浅主题变化。搜索采用正则表达式，仅过滤内容，不移除模块导航；保留历史、收藏和单元格复制。普通字段表保持可见行虚拟化，列标题以无障碍隐藏文本保留，不再单独占用一行。
- `AE_Table` 使用等宽数字矩阵，提供单块/全部统计选择、原始数字复制、横向滚动和 Shift + 滚轮；不创建像素图、Canvas 或直方图图形。直方图的 16 列是数值排版，不是空间网格。缺失或截短数据不补成看似有效的零矩阵。
- `Detail` 显示模块、精确头文件、匹配状态、原始版本字、签名与解码结果，共六列，不再显示“识别来源”列。后台仍保留识别来源契约用于兼容已有导出；头文件已匹配不等于其二进制布局已经解码。
- 旧 `native_merge` 文件及兼容 Rust 合并 API 的模块诊断按**当前保存的 TOML**重新聚合（按钮/IPC 已不再生成合并文件）：根级明确标签前缀和模块别名归入同一模块，重复数组逐值计数；AE_DISPLAY / Detail / AE_Table / 来源元信息不计入普通字段。合并业务模块每模块一行，头文件/版本/签名留空并标“未记录头文件”，不声称单一 JPEG 枚举解码了保留的 DP/手改字段；只有最新 native 检查的无内容模块及未知/冲突目录记录继续提供诊断。旧合并文件的累计诊断也在读取时归一化，**不重写自动复用的旧文件**，反复合并不会不断增加历史计数。
- 来源区只在 Detail 显示一个描述性徽标，路径在悬浮提示中；不再区分首次与最新。根据实际读取方式与 TOML 中 `parser/content_mode` 描述：`读取 TOML · 来源：JPEG 直接读取`、`读取 TOML · 来源：JPEG 直读与原 TOML 合并`、`读取 TOML · 来源：DebugParser.exe 解析覆盖`、来源未记录的旧 TOML，或无法识别需 DP 兜底。无标记文件不猜生成器。底层显式 JPEG 直读接口标为 `图片直接读取 · JPEG`，而普通点击始终标 TOML，不为显示来源再解码图片。
- 新生成的 TOML 随业务数据写入版本化的 `[__luxe_exif]` 来源元信息；显式覆盖不保留旧字段。该保留节与结构化 `AE_Table` 不进入图片列表的扁平关键字命名空间，避免 `parser`、`rows`、`values` 等通用叶名干扰原有字段。DebugParser 的 `[AE_Table]` 中 `<<块名>>` 和纯数字行按统计布局保存，不再被普通 `TAG:value` 提取器丢弃。

## 按钮与读取进度

- 左键显示 DP 覆盖确认框，说明替换当前目录图片的已有 TOML、原手动修改不保留；取消不启动工具，确认前换目录/索引则拒绝。右键直接读取当前目录 JPEG 并覆盖 TOML，不再依赖菜单，不执行删除 TOML/EXIF。三行操作提示使用委托 tooltip 的 `below-start / wrap / max-width=360`，防止长文字在默认 `nowrap` 下超出提示框。
- 右键原无响应的原因是 `main.tsx` 在 capture 阶段阻止原生 contextmenu，Fluent UI `MenuTrigger` 又因 `isDefaultPrevented()` 退出。现在本地 `onContextMenu` 明确阻止默认与冒泡后触发覆盖，不把全局禁用原生菜单当成禁止业务动作；空目录/任务中不触发。
- 写入均保留路径、同 stem 归属、link/reparse、只读/占用、16 MiB 文本、并发修改重验与原子替换边界。JPEG 与 DP 显式覆盖都允许以新有效结果替换 16 MiB 内损坏 UTF-8/TOML 文件，不解析旧业务，但仍读取原始字节快照用于并发重验；不绕过文件安全和权限。DP 整批复用同一目录 scope/inventory，避免每张图重复扫目录。
- 写入后清理后端字段缓存并刷新仍匹配的工作区，保留完成时用户的图片选择，递增 `metadataRevision` 使列表、热力图和详情失效。请求已发出后允许完成明确动作，但其结果不能覆盖新目录/索引；不执行删除 TOML/EXIF。
- `MetadataProgress.tsx` 只用于目录准备和手动 EXIF/DebugParser 任务，显示于图片列表卡片标题下的圆角、留白、语义主题状态区，不再在整个工作区上方插入薄色带，AE Basic/ToneMap 左右卡片顶边保持对齐。`QUEUED` 为排队，`PREPARE` 为逐张安全检查/复制，`DP` 为外部工具运行，`TOML` 为逐张转换/写入，`REFRESH` 为索引和当前字段刷新。准备/写入进度包含失败项，是真实已处理图数而非字节或剩余耗时；现有 DP 调用链未获得可靠百分比，固定发 `0/0`、使用 Fluent 不确定动画和说明，禁止伪造 `0/N → N/N` 或计时百分比。刷新期间仍显示状态，已完成任务的迟到 Channel 消息不能覆盖刷新状态。普通点击/切换 EXIF 标签只读准备后的 TOML，不创建进度 Channel 或反复显示进度条。
- 准备状态、进度和摘要放在同一 `imageDir` 瞬时状态中，回调校验目录、加载代次与任务仍有效；完成、失败和离开页面后，迟到消息不会重新打开进度或覆盖新数据集。不在前端驻留整目录完整 EXIF，批量字段仍只读取需要的键。

## 支持边界

实现参考 IPEParser 当前的 `mtk_3a_tool/mtk_3a_viewer.py`、`docs/mtk-exif.md` 与 `EXIF/` 枚举资源；旧 `MTK_3A_EXIF_Extraction_Guide.md` 已从参考项目删除，不再当作当前条件枚举和资源路径的依据。JPEG 直读运行时不依赖 IPEParser 目录、Python、Pillow、DP DLL 或额外子进程；手动兜底仍由用户配置的 DebugParser 提供。

| 模块 | 内置读取 |
| --- | --- |
| AE、Strobe、Shading | APP6 中有界定位的分片 KV；在已确认跨度补扫孤立记录 |
| AF | 图片目录版本 + APP6 稀疏记录；同一标签的重复数值以数组保留，数组内顺序不去重 |
| AWB、ISP | 第 6 代顺序小端 u32；第 5 代 APP7 KV |
| Common | APP5 稀疏 KV，遇到下一模块的 index-0 头停止 |
| MFNR | 第 5 代 APP5 稀疏 KV；第 6 代保留 DP 兜底 |
| Sensor、N3D、SWNR、BMDN | 识别指南中已知目录签名后标记需要兜底，不伪造字段 |

当前内置 **353 份第 5/6 代精确头文件**（13 个模块目录，共 22,037,931 字节，约 21.02 MiB），包含从当前 IPEParser 导入的规范资源及保留的 Samsung ISP 专用变体。`build.rs` 自动枚举规范命名的 `.h` / `.ha`，不再手工登记 18 个版本；添加资源后由 CI 重建并嵌入应用，运行时不读取外部 IPEParser 路径。资源预算为最多 512 文件、单文件 512 KiB、总量 32 MiB；不导入第 2/3/4 代、通用 MODULE.h 或 ISP_REG_CUSTOM 配置。Tauri 的 `bundle.resources` 不再单独复制头文件库，避免在可执行文件之外重复部署这份约 22 MB 的原始数据；仓库头文件仍保留供 CI 嵌入和测试。实际安装包体积变化等待 CI 产物确认。

资源存在不等于均可解码：资源审计明确保留并拒绝 13 份存在重复索引/无效声明的上游头文件；Detail 显示缺失、歧义、无效头文件或仅识别版本，不静默移位或改选其他版本。Node 资源审计不替代 Rust 枚举解析测试，后者仍等待 CI。支持边界如下，而非对任意 MTK 固件的兼容承诺：

- 版本由 APP6 代际魔数、图片目录版本和模块签名决定；不选本地“最高版本”。
- Samsung 与 M149 的同名 `ISP_6_10_2.h` 以签名区分；支持统一头文件中的 `MTK_EXIF_SIGNATURE ==/!=` 条件分支，并保留旧签名专用变体的精确优先级。缺少明确身份时不猜变体。
- 枚举按受限数据语法解析：注释、显式/隐式索引、前序枚举引用、括号和有界整数/位运算；单头最多 65,536 token，索引范围小于 16,384，表达式最多 128 token、嵌套深度 32，签名条件嵌套最多 16。只支持 include guard 与签名条件，不执行 C、include 或任意宏；非 guard 宏、未知指令、重复索引与越界会拒绝该模块，而不是猜值。
- 目录版本记录不能当作真实字段块。通过边界和 `4 + 32×记录数` 对齐校验的目录长度优先使用，不因首个模块含连续零值而扩大；无有效长度时才使用有界模块数量/保留字回扫。
- 第 6 代 AWB/ISP 数组必须容纳精确枚举的全部数值；目录记录按原始序号绑定自身 APP 段中的 payload，数组只在所属容器内定位，不能借用其他模块中恰好相同的版本数值。空容器保留原始槽位；无效的多容器偏移表不退化为整段扫描，单容器单声明旧布局保留兼容。截短或边界不明的数组即使同图 AE 正常也保留 `needs_fallback`；导入缓存可保存已支持字段，但不能宣称该图片完整。
- 已声明的 AF/Common/MFNR 解码为空时保留 `needs_fallback`；AF 的版本与首个 key 后必须有完整数值记录，不能仅凭截断锚点把该模块判为成功。其他可确认字段可保存为带未补全标志的 TOML，不得因该文件已存在阻断后续 DP 重试。
- 重复模块声明（含同版本重复）和多个同 marker 的 index-0 数据块不被混合命名；受影响模块停止直接解码，其余可确认的字段仍可用。KV 块版本须与选中枚举一致，后续 index-0 头不是分片延续。
- 任意 APP5/6/7 中的未知目录声明都保留兜底资格；新签名只允许在其有效所属块内，按精确版本、块头/枚举索引与完整布局唯一推断模块，后台识别来源保留为 `directory_layout`（UI 已移除该列）。无法唯一归属时不猜模块或枚举；同 marker 的搜索不能跨 APP 段或串入下一个 APP5 模块。
- 保留项目已有的 AE/ISP 关键字链路，新增私有统计与诊断，不移植参考工具的图片预览或标准 EXIF 摘要。标准 ISO 与 AE 实时 ISO 不被混写。
- AF 的 TOML 按标签保存重复值数组，不提供跨标签的完整时间线查看器。
- 同一 stem 的 JPG/JPEG/PNG 无法通过逻辑 TOML 路径唯一定位时，直接读取和导出拒绝猜测；已存在的 TOML 仍按原兼容规则读取。

## AE_Table 布局边界

统计矩阵与普通枚举标签分别解析，不从标签数推算网格大小：

| 布局 | 读取与输出边界 |
| --- | --- |
| 第 6 代 type8 | APP6 中有界定位统计记录；连续读取两份 5×5、五份 15×15 的 u16 小端网格，以及 Central_Y / Full_Y / Full_RGB 三份 1024-bin **u24** 小端直方图。需有完整字节范围、有效网格变化及 Full_RGB/Full_Y 总量一致性；不得把 u24 当 u32。 |
| 第 6 代 type10 revision 1 | 有效 offset 范围内校验 `0x0001000A` 记录与 `(64,48,8,6)` 布局；四通道各保留 256 个 u16，仅取前 48 个为 **6 行 × 8 列**。后接三份 256-bin u32 直方图；不把布局标记 64×48 当实际输出网格。 |
| 第 5 代 AE 标签重建 | 从精确枚举对应的 AE 标签还原 5×5、15×15 RGBY/OverCnt 和四份 128-bin HIST；RGBY 按同一个 u32 的四个字节拆分。枚举未声明的 bin 才允许填 0；已声明却缺失的数据不能伪造为完整矩阵。 |
| DebugParser TOML | `[AE_Table]` 的 `<<块名>>` 加纯数字行转为带 `rows` / `columns` / `values` 的子表；保留第 5 代含空格的块名。自动导入复用；右键会以 JPEG 本次有效结果完整替换，DP 特有统计不会继承。普通切图不另从图片补入。截短和形状不一致的数组不展示。 |

这些是已实现布局的约束，不是本次真实 JPEG / DebugParser 逐字段对照结果。未知修订或未确认布局仍需兜底。

## 读取、第三方库与性能边界

- **自动 TOML 热路径**：自动导入先验证同名 TOML；合法时原字节复用，只做一次有界读取/解析以校验文件与状态，跳过 JPEG I/O、native 解码、比较指纹、重序列化和来源重写。缺失才解码 JPEG。自动导入仍尊重用户改动的旧 TOML；只有显式右键覆盖才放弃旧业务内容，以免每次重开都成为隐式对账。显式覆盖不解析旧 TOML，只保留有界原字节快照用于安全写入检查，省去旧文档解析与字段/数组/统计比较合并。
- **读取方式**：Rust `BufReader` 使用 64 KiB 缓冲扫描 JPEG marker，遇到 SOS/EOI 即停止，保留 APP5/6/7，seek 跳过 APP1 标准 EXIF/缩略图、XMP 与像素解码表。不解码压缩像素、不读取整张 JPEG；跳过段仍计入 16 MiB header 扫描预算，截短文件仍失败。
- **指令集**：`memchr = 2.8.0` 的 `memmem` 执行有界小端 word 搜索，默认 `std` 按 CPU 运行时分派；支持时可用 AVX2，不支持时使用兼容路径，无 `target-cpu=native` 或强制 AVX2。它只加速候选字节查找，不替代版本、完整跨度、模块自有容器与重复声明校验。TurboJPEG 的 `require-simd` 用于预览像素解码，不等于私有 EXIF 的硬件加速。
- **TOML 方式**：继续使用锁文件中的 `toml 0.8.2`（Serde/`toml_edit` 后端）做完整解析/序列化；按键读取仍有既有 fast-parser 与完整 TOML 回退。新 native 保存流程仅把 native 文本解析一次，直接在 root 插入来源后最终序列化一次，删除旧多轮 stamp/serialize/parse 和全量指纹遍历。DP 文本转换同样直接在已解析 root 中插入来源后序列化一次，不再先生成展示字段字符串、再经历一次完整输出→解析。未在缺少基准的情况下升级到另一套 TOML 库；改格式库不能解决重复读图、重复 DOM 和全段扫描。
- **线程**：复用锁定 `Rayon 1.10.0`，全局元数据池按可用核数限制为 1–2 worker；每个 worker 循环单图处理，最多两张图文档并行，不为目录每张图各自 spawn 或 collect 全部结果。有界 channel 只传轻量完成消息，调用线程汇总单调进度。双线程可增加峰值单图对象数量，仍是常量上限，不宣称已经实测更低进程内存。
- **局部枚举与分配**：单次 inspection 的精确头文件+签名缓存最多 16 个身份、估算枚举向量不超过 2 MiB，调用结束即释放；同名 ISP 签名分支与失败结果隔离。头部选择避免多份候选 Vec，枚举名使用哈希查找/有界索引向量；KV 分片复用目标 map、统计 type8 不再重扫两遍，数值数组直接写入 String，移除 `Vec<String> + join` 中间分配。这些是代码级优化，不是墙钟或进程内存实测。

- JPEG 使用 64 KiB 缓冲读取，在 SOS/EOI 停止；元数据累计上限 **16 MiB**。不读取完整压缩像素流，不进行像素解码、缩略图生成、Canvas 或 Blob 分配。
- TOML/EXIF 文本读取同样有 **16 MiB** 上限；损坏段长度、截断文件与非 JPEG 返回明确失败，不无限扫描。
- 全字段和按键缓存复用原 `TOML_CACHE` / `TOML_FIELD_CACHE`：上限分别为 **96 项且估算有效载荷不超过 16 MiB**、**512 项且不超过 8 MiB**，按 LRU 淘汰；大于单个预算的条目不驻留。
- 批量字段请求只向前端返回所需键；当前图片已在全字段缓存时，直接抽取字段，不再次解析其 JPEG。列表不保留整目录的完整 EXIF 对象。
- 普通元数据 IPC 最多 2 个任务并发，导入/覆盖/DP 批任务最多 1 个；JPEG 工作由共享池最多两张并行，DP 外部工具运行一次、写出逐张处理。头文件文本引用编译内不可变字符串；仅为本次图片解析需要的枚举向量，结束即释放，不建立随版本/签名不断增长的枚举缓存，也不缓存图片字节。详情模块诊断最多 256 行；超出预算保留兜底资格。
- 原 `clear_memory_caches()` / `trimMemory(true)` 会清除两类缓存并递增代次，旧任务不能重新填入已清理缓存。缓存锁不跨文件读取或解析。
- 左键显式 DP 覆盖复制当前目录中全部通过安全预检的图片，不因已有 TOML 完整而跳过；临时目录以进程和时间隔离并通过 RAII 清理。TOML 在目标目录写临时文件后 rename，失败清理临时文件。
- `src/services/imageExifService.ts` 统一导入准备及完成后的共享目录刷新，任务不会因 AE Basic/ToneMap 切页卸载而丢失收尾；同一工作区的导入/覆盖/解析互斥，各类进行中任务最多 16 个且结束即移除，不缓存完成结果。磁盘 TOML 是有界合法性验证的持久缓存，内存仅使用原有预算与当前详情文档。
- 刷新保留用户**完成时**的选择。临时 `metadataRevision` 使两页的会话缓存、图片列表和打开着的 EXIF 详情同时失效；实际文件加载用独立 `loadRevision`，不被配对选中同一路径的意图错误取消。目录换代、真实 A→B→A 加载及卸载后的局部结果不能覆盖新工作区。
- `loadImageTomlFieldsBatchShared` 必须接收 `{ entries, revision }`：仅在同一索引对象与内容代次内复用进行中的字段请求，成功/失败后均释放槽位，弱引用索引不保留完成结果。列表可见行、预取、分类、排序、Apply 与 AE/ToneMap 热力图均使用同一身份；原生 JPEG→TOML 切换后，不因路径和键相同复用旧请求。列表提交/卸载时同步隔离旧代次，每个代次独立拥有 loading 集合，旧请求的成功、失败及 `finally` 都不能污染新缓存或清除新请求标记。

这些是实现预算，不是实际进程内存或 CPU 降幅。真实性能需按 `docs/performance/MEMORY_RECOVERY.md` 对相同构建、同一数据集分别采样宿主、WebView2 browser、renderer、GPU。
