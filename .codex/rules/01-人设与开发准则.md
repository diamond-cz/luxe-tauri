# 人设与开发准则

## 适用范围

适用于本仓库所有前端、Rust、脚本、配置和文档改动。规则目录为 D:\Image_process\luxe-tauri\.codex\rules；项目根目录为 D:\Image_process\luxe-tauri。

## 规则条目

### R01: 先确认现状

**断言**：修改前先检查 `git status --short`，再阅读相关入口、状态、IPC 和测试。必须保留已有未提交改动。

**示例**：

~~~powershell
git status --short
rg -n "saveImageTableMode|save_image_table_mode" src src-tauri/src
~~~

**违规特征**：未读现有代码就新建重复逻辑，或清除用户的未提交文件。

### R02: 限定改动边界

**断言**：代码放在负责该功能的目录。图片表格列设置放在 `src/views/mtk/isp6s/TablePane/`；跨页面复用逻辑才放入 `src/components/`、`src/services/` 或 `src/ipc/`。

**示例**：

~~~text
src/views/mtk/isp6s/TablePane/ColumnSettingsWindow.tsx
src/views/mtk/isp6s/TablePane/imageTableColumnSettings.ts
~~~

**违规特征**：为单个表格需求修改全局应用入口，或在视图文件中复制已有的 IPC 封装。

### R03: 交付验证结果

**断言**：交付时列出实际运行的命令、结果和未执行的验证。前端改动至少运行 `npm run typecheck`；本地 Rust 改动仅运行不编译的静态检查，Rust 编译和测试由 `.github/workflows/ci.yml` 执行，不得本地运行 Cargo 编译或测试命令。

**示例**：

~~~text
验证：npm run typecheck（通过）；Node 脚本测试（通过）；Rust 编译与测试：等待 GitHub Actions。
限制：未在 Tauri 窗口中手动检查多显示器位置。
~~~

**违规特征**：未运行验证却声称已通过，或把编译通过写成桌面端交互已经验收。

### R04: 先核对语言契约

**断言**：涉及语言选择、翻译资源或 `settings.language` 的改动，必须同时核对 `src/locales/index.ts`、`src-tauri/src/config/translations.rs`、`src-tauri/resources/translations/` 和 `src/types/ipc.ts`；五种语言及其顺序必须完全一致：`zh_CN`、`zh_TW`、`en_US`、`ja_JP`、`tr_TR`。

**示例**：

~~~text
src/locales/index.ts
src-tauri/src/config/translations.rs
src-tauri/resources/translations/{zh_CN,zh_TW,en_US,ja_JP,tr_TR}.json
src/types/ipc.ts
~~~

**违规特征**：只修改设置下拉框，或只删除 JSON 文件而未同步 Rust 常量和持久化索引。

### R05: 先定义跨进程行为契约

**断言**：新增跨进程联动前，必须在 `src/types/` 定义版本化消息结构，并在 `docs/engineering/` 记录消息方向、绝对路径身份、目录到工作区映射、确认、去重、断线和权限；不得先写 UI 或绑定某一种传输实现。

**示例**：

~~~ts
export interface ImageSelectionMessage {
  protocolVersion: 1;
  sourceInstance: string;
  sequence: number;
  imagePath: string;
}
~~~

**违规特征**：在组件中直接调用命名管道或 TCP，依赖未经核实的 HiViewer callback，或未定义路径找不到时仍盲目改变当前索引。
