# 人设与开发准则

## 适用范围

适用于本仓库所有前端、Rust、脚本、配置和文档改动。规则目录为 D:\Image_process\luxe-tauri\.codex\rules；项目根目录为 D:\Image_process\luxe-tauri。

## 规则条目

### R01: 先确认现状

**断言**：修改已有功能前，必须读取其入口、对应状态或 IPC 实现，以及 git 工作区状态；提交的改动不能覆盖用户已有修改。合规记录应能指出被修改的现有入口。

**示例**：

~~~powershell
git status --short
rg -n "saveImageTableMode|save_image_table_mode" src src-tauri/src
~~~

**违规特征**：只凭需求描述新建一套状态写入逻辑，或以重置工作区的方式清除未提交文件。

### R02: 限定改动边界

**断言**：功能代码应写入所属模块；图片表格的列设置修改位于 D:\Image_process\luxe-tauri\src\views\mtk\isp6s\TablePane，跨页面复用逻辑才进入 src/components、src/services 或 src/ipc。

**示例**：

~~~text
src/views/mtk/isp6s/TablePane/ColumnSettingsWindow.tsx
src/views/mtk/isp6s/TablePane/imageTableColumnSettings.ts
~~~

**违规特征**：为单个表格需求修改全局应用入口，或在视图文件中复制已有的 IPC 封装。

### R03: 交付验证结果

**断言**：完成改动时必须列出实际运行的验证命令、结果及未执行的相关验证；前端改动至少运行 npm run typecheck，Rust 行为改动运行 npm run rust:test。

**示例**：

~~~text
验证：npm run typecheck（通过）；npm run build（通过）。
限制：未在 Tauri 窗口中手动检查多显示器位置。
~~~

**违规特征**：未运行验证却声称已通过，或把编译通过写成桌面端交互已经验收。
