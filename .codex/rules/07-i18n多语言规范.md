# i18n 多语言规范

## 适用范围

适用于 `src/locales/` 的 i18next 23.16.8 运行时、`src-tauri/src/config/translations.rs` 和翻译资源目录。当前版本固定支持五种语言。

## 规则条目

### R01: 语言列表双端一致

**断言**：语言代码和顺序必须在 `src/locales/index.ts` 与 `src-tauri/src/config/translations.rs` 保持一致，因为该顺序对应 `state.toml` 的语言索引。

**示例**：

~~~ts
export const LANGUAGE_LOCALES = [
  "zh_CN", "zh_TW", "en_US", "ja_JP", "tr_TR",
] as const;
~~~

**违规特征**：只在前端插入一个语言代码，导致已有 settings.language 索引指向另一种语言。

### R02: 新增文案补齐资源

**断言**：新增用户文案的 key 必须存在于 `src-tauri/resources/translations/{zh_CN,zh_TW,en_US,ja_JP,tr_TR}.json`；改名时同步修改资源和调用点。

**示例**：

~~~tsx
import { useTranslation } from "react-i18next";

const { t } = useTranslation();
return <span>{t("column_settings.title")}</span>;
~~~

**违规特征**：仅在 zh_CN.json 添加新键，其他语言界面直接显示键名或固定中文。

### R03: 沿用启动加载入口

**断言**：前端使用 `src/locales/i18n.ts` 的单例；资源通过 Rust 的 `get_all_locale_bundles` 加载；默认和回退语言为 `zh_CN`。

**示例**：

~~~ts
import { bootstrapI18n } from "@/locales/i18n";
import { localeAt } from "@/locales";

await bootstrapI18n(localeAt(settings.language));
~~~

**违规特征**：单个窗口创建第二个 i18next 实例，或绕过现有 IPC 加载路径读取资源。

### R04: 动态内容使用插值

**断言**：包含版本号、文件名或数值的用户文案须通过翻译键插值；数字、路径和公式本身保持原始数据格式。

**示例**：

~~~tsx
<span>{t("update.current_version", { version: currentVersion })}</span>
~~~

**违规特征**：用中文字符串拼接版本号，造成其他语言词序无法调整。

### R05: 联动文案只进入当前五种语言

**断言**：图片联动开关、连接状态、路径不匹配和协议错误的用户可见文本必须使用翻译 key，并在 `src-tauri/resources/translations/{zh_CN,zh_TW,en_US,ja_JP,tr_TR}.json` 中提供对应条目；协议字段、reason code 和日志事件名使用稳定英文标识，不参与本地化。

**示例**：

~~~ts
t("image_sync.status.connected");
t("image_sync.error.image_not_indexed");
// IPC code remains stable across locales.
{ accepted: false, reason: "image-not-indexed" }
~~~

**违规特征**：把翻译后的中文状态字串当作 IPC reason，或只在 zh_CN 中添加联动提示。
