# i18n 多语言规范

## 适用范围

适用于 D:\Image_process\luxe-tauri\src 下的用户可见文案与 src-tauri/resources/translations 的 16 份语言资源。前端使用 i18next 23.16.8 和 react-i18next 15.7.4。

## 规则条目

### R01: 语言列表双端一致

**断言**：语言的顺序和代码必须在 src/locales/index.ts 的 LANGUAGE_LOCALES 与 src-tauri/src/config/translations.rs 的 LANGUAGE_LOCALES 保持一致；该顺序对应 state.toml 中 settings.language 的持久化索引。

**示例**：

~~~ts
export const LANGUAGE_LOCALES = [
  "zh_CN", "zh_TW", "en_US", "ja_JP", "ko_KR",
  "de_DE", "fr_FR", "es_ES", "pt_BR", "ru_RU",
  "it_IT", "tr_TR", "pl_PL", "cs_CZ", "vi_VN", "ar_SA",
] as const;
~~~

**违规特征**：只在前端插入一个语言代码，导致已有 settings.language 索引指向另一种语言。

### R02: 新增文案补齐资源

**断言**：新增可见文案的翻译键必须存在于 src-tauri/resources/translations 的全部 16 个 JSON 文件；修改键名时同步迁移所有资源与调用点。

**示例**：

~~~tsx
import { useTranslation } from "react-i18next";

const { t } = useTranslation();
return <span>{t("column_settings.title")}</span>;
~~~

**违规特征**：仅在 zh_CN.json 添加新键，其他语言界面直接显示键名或固定中文。

### R03: 沿用启动加载入口

**断言**：前端翻译使用 src/locales/i18n.ts 初始化的单例；语言资源通过 get_all_locale_bundles 从 Rust 加载，不在组件中自行 fetch 翻译 JSON。默认与回退语言为 zh_CN。

**示例**：

~~~ts
import { bootstrapI18n } from "@/locales/i18n";
import { localeAt } from "@/locales";

await bootstrapI18n(localeAt(settings.language));
~~~

**违规特征**：单个窗口创建第二个 i18next 实例，或绕过现有 IPC 加载路径读取资源。

### R04: 动态内容使用插值

**断言**：包含版本号、文件名或数值的用户文案须通过翻译键插值；数字、路径和公式本身保持原始数据格式。

**示例**：

~~~tsx
<span>{t("update.current_version", { version: currentVersion })}</span>
~~~

**违规特征**：用中文字符串拼接版本号，造成其他语言词序无法调整。
