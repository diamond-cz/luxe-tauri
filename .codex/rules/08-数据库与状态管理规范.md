# 数据库与状态管理规范

## 适用范围

适用于 Zustand 5.0.9 前端状态、Rust TOML 持久化和 `settings.language` 迁移。本项目当前没有独立数据库；持久化文件由 `src-tauri/src/config/state_file.rs` 管理。

## 规则条目

### R01: 区分临时状态和持久状态

**断言**：弹窗和加载状态留在组件或现有 store。重启后要恢复的配置必须通过 `src/ipc/stateIo.ts` 写入 TOML，不能只写 localStorage。

**示例**：

~~~ts
const state = await loadState();
await saveStateSection("settings", { ...state.settings, theme: "light" });
~~~

**违规特征**：界面显示配置已保存，但重启后依赖 localStorage 或组件状态恢复，导致 TOML 与 UI 不一致。

### R02: 双端数据契约同步

**断言**：修改持久化字段时，同时检查 `state_schema.rs`、`src/types/ipc.ts`、默认值、旧 TOML 兼容和 Rust 测试。

**示例**：

~~~text
Rust: src-tauri/src/config/state_schema.rs
TypeScript: src/types/ipc.ts
兼容验证: src-tauri/tests/ 或 state_schema.rs 的测试
~~~

**违规特征**：只调整 TypeScript 类型，Rust 反序列化后丢弃字段；新增非可选字段导致旧 state.toml 无法读取。

### R03: 复用串行写入与落盘入口

**断言**：持久化通过 `src/ipc/stateIo.ts` 写入。关闭窗口前必须等待保存操作和 `flushStateNow()` 完成。

**示例**：

~~~ts
await saveImageTableMode(mode, modeSettings, legacyOther);
await flushStateNow();
await getCurrentWindow().close();
~~~

**违规特征**：调用保存后立即关闭窗口且不等待，或绕过现有串行队列并发覆盖同一 TOML 字段。

### R04: 表格列设置按模式与标签管理

**断言**：`isp6s` 与 `tone` 使用 `image_table_columns` 中各自的分支。`isp6s` 的 `all`、`face`、`normal` 分别保存列状态；Tone 只使用 `all`。预览只更新主表格；未保存关闭时恢复已保存配置。

**示例**：

~~~ts
const mode = tone ? "tone" : "isp6s";
const scope = "all";
const columns = state.image_table_columns?.[mode]?.[scope];
~~~

**违规特征**：Face 隐藏一列后 All 也被隐藏，或 ToneMap 保存时覆盖 isp6s 的列配置。

### R05: 颜色阈值只保存一份

**断言**：AEGain、EV 和 CWR 差值阈值只持久化一份；`All`、`Face`、`Normal` 共用该配置，Tone 模式读取 `All`。

**示例**：

~~~ts
const thresholds = state.image_table_columns?.isp6s.color_thresholds;
const toneThresholds = thresholds;
~~~

**违规特征**：每个标签各自保存阈值，或 Tone 使用独立配置。

### R06: 语言索引迁移不可错映射

**断言**：`StateStore::load` 必须调用 `migrate_locale_index`；旧索引 `11`（tr_TR）迁移为 `4`，其他已删除语言索引回退为 `0`，并写入 `locale_schema_version = 1`。

**示例**：

~~~rust
state.settings.language = match old_index { 11 => 4, 0..=3 => old_index, _ => 0 };
~~~

**违规特征**：直接截断旧索引，导致旧土耳其语显示为其他语言。

### R07: 外部图片选择更新既有工作区状态

**断言**：外部进程选中的图片必须映射到 `useMtkStore.imageDir[workspaceKey]` 中已扫描的 `entries`，通过唯一 store action 更新 `current`，并同步 `imageSelection[workspaceKey]`；工作区键使用现有 `${IspId}|${tabIdx}` 形式，禁止新建平行索引 store。

**示例**：

~~~ts
function selectExternalImage(workspaceKey: string, imagePath: string) {
  const image = useMtkStore.getState().imageDir[workspaceKey];
  const current = image?.entries.findIndex((entry) => sameAbsolutePath(entry.jpg_path, imagePath)) ?? -1;
  if (!image || current < 0) return { accepted: false as const, reason: "image-not-indexed" };
  useMtkStore.getState().setExternalImageSelection(workspaceKey, current, imagePath);
  return { accepted: true as const };
}
~~~

**违规特征**：只改组件 `useState`、仅更改 `imageSelection` 却不改索引 `current`，或把外部进程游标另存为第二份持久状态。

### R08: 工作区映射按目录且不隐式扫描

**断言**：外部路径按其父目录与 `imageDir[workspaceKey].dir` 的规范化绝对路径比较；只有一个已扫描目录精确命中时才更新该 workspace。零个或多个候选时返回 `image-not-indexed` 或 `ambiguous-workspace`，不能隐式启动目录扫描或选择第一个候选。

**示例**：

~~~ts
const matches = Object.entries(imageDir).filter(([, state]) =>
  sameAbsolutePath(state.dir, dirname(message.imagePath)));
if (matches.length !== 1) return { accepted: false, reason: "ambiguous-workspace" };
~~~

**违规特征**：使用文件名选择 workspace、在通信回调里静默扫描任意目录，或当两个 workspace 指向同一目录时随机选一个。

### R09: 持久化配置与瞬时会话分离

**断言**：用户明确配置的联动启用状态和传输偏好可经 `src/ipc/stateIo.ts` 持久化到 TOML；socket/pipe handle、连接令牌、最近序号、待确认消息和当前会话 sourceInstance 仅保存在内存中，应用退出后必须重新握手。

**示例**：

~~~ts
type ImageSyncPreferences = { enabled: boolean; transport: "named-pipe" | "loopback" };
type ImageSyncSession = { connected: boolean; sourceInstance: string; lastSequence: number };
~~~

**违规特征**：把系统句柄或 bearer token 写进 state.toml，或重启后复用未经重新验证的旧连接状态。
