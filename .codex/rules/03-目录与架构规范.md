# 目录与架构规范

## 适用范围

适用于 D:\Image_process\luxe-tauri\src、src-tauri、scripts、docs 和 .github 的新增或迁移文件。前端 @/ 别名由 tsconfig.json 映射到 src/。

## 规则条目

### R01: 按职责放置前端代码

**断言**：页面放在 `src/views/`，跨页面组件放在 `src/components/`，共享状态放在 `src/stores/`，IPC 封装放在 `src/ipc/`，服务逻辑放在 `src/services/`，共享类型放在 `src/types/`。

**示例**：

~~~text
src/views/mtk/isp6s/TablePane/TablePane.tsx
src/stores/settingsStore.ts
src/ipc/stateIo.ts
src/types/ipc.ts
~~~

**违规特征**：在页面组件中直接定义可被多页面调用的状态写入协议，或将业务视图放入 src/components/common。

### R02: 使用已配置的导入路径

**断言**：跨目录导入使用 `@/*`；同目录导入使用相对路径。新别名必须同时配置到 Vite 和 TypeScript。

**示例**：

~~~ts
import { loadState } from "@/ipc/stateIo";
import { normalizeColumnMode } from "./imageTableColumnSettings";
~~~

**违规特征**：跨层使用多级 ../../../../ 路径，或仅在编辑器配置中声明新别名。

### R03: Rust 命令保持双端对应

**断言**：新增 Tauri 命令时，必须同步修改 Rust 实现、`src-tauri/src/lib.rs` 注册、`src/ipc/` 封装和 `src/types/ipc.ts` 类型。

**示例**：

~~~text
src-tauri/src/commands/state_cmds.rs: save_image_table_mode
src-tauri/src/lib.rs: generate_handler! 中注册命令
src/ipc/stateIo.ts: saveImageTableMode
src/types/ipc.ts: ImageTableModeColumns
~~~

**违规特征**：只添加 Rust 命令而未注册，或前端散落字符串命令名与无类型的参数对象。

### R04: 文档进入既有索引

**断言**：新增功能或性能专题文档应放入 docs 对应领域目录，并同步更新 docs/README.md；规则文件只放在 .codex/rules。

**示例**：

~~~text
docs/performance/MEMORY_RECOVERY.md
docs/features/FACE_TABLE_HEATMAP.md
docs/README.md
~~~

**违规特征**：专题说明散落在 src/ 下，或新增 docs 文件却未加入文档索引。
