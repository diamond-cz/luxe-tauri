# 目录与架构规范

## 适用范围

适用于 D:\Image_process\luxe-tauri\src、src-tauri、scripts、docs 和 .github 的新增或迁移文件。前端 @/ 别名由 tsconfig.json 映射到 src/。

## 规则条目

### R01: 按职责放置前端代码

**断言**：页面放在 `src/views/`，跨页面组件放在 `src/components/`，共享状态放在 `src/stores/`，IPC 封装放在 `src/ipc/`，服务逻辑放在 `src/services/`，共享类型放在 `src/types/`。

**示例**：

~~~text
src/views/mtk/isp6s/TablePane/TablePane.tsx
src/stores/settingsStore.ts
src/ipc/stateIo.ts
src/types/ipc.ts
~~~

**违规特征**：在页面组件中直接定义可被多页面调用的状态写入协议，或将业务视图放入 src/components/common。

### R02: 使用已配置的导入路径

**断言**：跨目录导入使用 `@/*`；同目录导入使用相对路径。新别名必须同时配置到 Vite 和 TypeScript。

**示例**：

~~~ts
import { loadState } from "@/ipc/stateIo";
import { normalizeColumnMode } from "./imageTableColumnSettings";
~~~

**违规特征**：跨层使用多级 ../../../../ 路径，或仅在编辑器配置中声明新别名。

### R03: Rust 命令保持双端对应

**断言**：新增 Tauri 命令时，必须同步修改 Rust 实现、`src-tauri/src/lib.rs` 注册、`src/ipc/` 封装和 `src/types/ipc.ts` 类型。

**示例**：

~~~text
src-tauri/src/commands/state_cmds.rs: save_image_table_mode
src-tauri/src/lib.rs: generate_handler! 中注册命令
src/ipc/stateIo.ts: saveImageTableMode
src/types/ipc.ts: ImageTableModeColumns
~~~

**违规特征**：只添加 Rust 命令而未注册，或前端散落字符串命令名与无类型的参数对象。

### R04: 文档进入既有索引

**断言**：新增功能或性能专题文档应放入 docs 对应领域目录，并同步更新 docs/README.md；规则文件只放在 .codex/rules。

**示例**：

~~~text
docs/performance/MEMORY_RECOVERY.md
docs/features/FACE_TABLE_HEATMAP.md
docs/README.md
~~~

**违规特征**：专题说明散落在 src/ 下，或新增 docs 文件却未加入文档索引。

### R05: 语言资源按双端边界维护

**断言**：前端语言契约只能放在 `src/locales/index.ts` 与 `src/locales/i18n.ts`，Rust 语言契约只能放在 `src-tauri/src/config/translations.rs`，翻译 JSON 只能放在 `src-tauri/resources/translations/`；该目录只允许 `zh_CN.json`、`zh_TW.json`、`en_US.json`、`ja_JP.json`、`tr_TR.json`。

**示例**：

~~~text
src/locales/index.ts
src/locales/i18n.ts
src-tauri/src/config/translations.rs
src-tauri/resources/translations/zh_CN.json
~~~

**违规特征**：在视图组件内维护另一份语言数组，或在资源目录保留已移除语言的 JSON 文件。

### R06: 跨进程同步按传输适配器分层

**断言**：跨进程消息契约放在 `src/types/imageSync.ts`，选择路由和会话编排放在 `src/services/imageSyncService.ts`，Tauri 本地 IPC 封装放在 `src/ipc/`，Windows Named Pipe 的系统适配放在 `src-tauri/src/image_sync/`；React 页面不得直接访问操作系统传输接口。

**示例**：

~~~text
src/types/imageSync.ts
src/services/imageSyncService.ts
src/ipc/imageSync.ts
src-tauri/src/image_sync/mod.rs
~~~

**违规特征**：将消息 JSON、Named Pipe 生命周期或工作区查找逻辑塞入 `ImagePane.tsx`、`TablePane.tsx`，或让插件协议类型散落在多处重复声明。

### R07: 图片路径优先且候选唯一匹配

**断言**：跨进程消息中的活动图片路径必须是绝对路径；LUXE 在已加载 `imageDir` 索引中先按规范化完整路径匹配，再仅对全局唯一文件名回退；路径/名称多重命中和零命中均不得猜测或切换索引。

**示例**：

~~~ts
const exact = loadedEntries.filter((entry) => normalizePath(entry.jpg_path) === normalizePath(path));
const byName = exact.length ? [] : loadedEntries.filter((entry) => basename(entry.jpg_path) === basename(path));
const match = exact.length === 1 ? exact[0] : exact.length === 0 && byName.length === 1 ? byName[0] : null;
~~~

**违规特征**：只比较文件名而不检查全局唯一性，或在多重命中时任意切换到某张图片。
### R08: 多候选图片联动匹配

**断言**：跨进程 `imagePaths` 按活动焦点优先排列；LUXE 先在已加载 `imageDir` 中按规范化完整路径精确匹配，精确路径无命中时仅允许全局唯一文件名回退，零命中或多重命中不得猜测工作区或切换索引；单路径 `imagePath` 仅用于兼容旧协议。

**示例**：
```ts
const paths = [...(message.imagePaths ?? []), ...(message.imagePath ? [message.imagePath] : [])];
const exact = loadedEntries.filter((entry) => normalizePath(entry.jpg_path) === normalizePath(paths[0]));
const nameMatches = exact.length ? [] : loadedEntries.filter((entry) => basename(entry.jpg_path) === basename(paths[0]));
const match = exact.length === 1 ? exact[0] : exact.length === 0 && nameMatches.length === 1 ? nameMatches[0] : null;
```

**违规特征**：把 HiViewer 的完整导航列表无条件当作当前选择，或在文件名重名、同一路径落入多个 LUXE 工作区时任意切换。
