# 通信与数据获取规范

## 适用范围

适用于 React 与 Rust 间的 Tauri 2.12.4 IPC、事件、capability，以及 GitHub 更新请求和安装包下载。现有入口包括 src/ipc/client.ts、src-tauri/src/commands、src-tauri/src/lib.rs 和 src-tauri/capabilities/default.json。

## 规则条目

### R01: 命令通过类型化 IPC 封装

**断言**：页面调用 Rust 时，必须经过 `src/ipc/` 的类型化封装和 `src/ipc/client.ts` 的 `call<T>()`；命令名、参数和返回类型必须一致。

**示例**：

~~~ts
import { call } from "@/ipc/client";
import type { StateRoot } from "@/types/ipc";

export const loadState = () => call<StateRoot>("load_state");
~~~

**违规特征**：在多个视图中重复 invoke("load_state")，或使用 any 掩盖前后端契约不匹配。

### R02: 注册命令并收敛权限

**断言**：新增 Tauri 命令必须注册到 `src-tauri/src/lib.rs` 的 `generate_handler!`；新增窗口或插件能力必须检查 `src-tauri/capabilities/default.json`，只增加需要的权限。

**示例**：

~~~text
src-tauri/src/commands/state_cmds.rs
src-tauri/src/lib.rs
src-tauri/capabilities/default.json
~~~

**违规特征**：Rust 命令已经实现但未注册，或为一个窗口操作启用无关的全局文件系统权限。

### R03: 事件要有发送与接收契约

**断言**：跨窗口事件使用共享常量；payload 带上识别目标所需字段；监听器卸载时解除订阅；过期事件不能覆盖新状态。

**示例**：

~~~ts
await emit(COLUMN_SETTINGS_SAVED_EVENT, { mode, settings: modeSettings });
~~~

**违规特征**：多个文件各自硬编码不同事件字符串，或窗口卸载后仍保留监听器。

### R04: 更新链路保持代理与签名校验

**断言**：客户端检查更新使用 @tauri-apps/plugin-updater 的 check()；远程 latest.json 端点和发布清单中的 GitHub 安装包地址按现有 gh-proxy.com 方案代理，安装仍由 Tauri updater 校验签名。变更发布资产名称时必须同步核对工作流和更新清单生成脚本。

**示例**：

~~~json
"endpoints": ["https://gh-proxy.com/https://github.com/diamond-cz/luxe-tauri/releases/latest/download/latest.json"]
~~~

**违规特征**：直接 fetch 安装包并执行未经签名验证的文件，或只改客户端 URL 而未核对 latest.json 的资产地址。

### R05: 语言资源通过既有 IPC 加载

**断言**：前端只能通过 `src/ipc/shell.ts` 的 `get_all_locale_bundles()` 调用 Tauri `get_all_locale_bundles`，并只注册五个白名单语言；Rust `list_locales` 返回顺序必须与 `LANGUAGE_LOCALES` 相同。

**示例**：

~~~ts
export const getAllLocaleBundles = () =>
  call<Record<string, Record<string, string>>>("get_all_locale_bundles");
~~~

**违规特征**：组件直接读取资源文件、前端自行 fetch 未注册的语言，或 IPC 返回包含已删除语言。

### R06: 语言 IPC 失败要安全回退

**断言**：语言资源加载失败或 `settings.language` 超出 `0..4` 时，启动流程必须回退到 `zh_CN`，且不得阻塞主窗口渲染；错误必须通过现有日志入口记录。

**示例**：

~~~ts
const lang = localeAt(settings.language); // 非法索引回退 zh_CN
void bootstrapI18n(lang).catch((err) => console.warn("i18n bootstrap failed", err));
~~~

**违规特征**：IPC 异常导致白屏，或把非法索引传给 `changeLanguage` 后显示 key 字符串。

### R07: HiViewer 插件只承担宿主事件接入

**断言**：HiViewer 插件端依据 `plugins/plugin-development-guide.md` 的 `native-view`/`ViewerSnapshot` 契约接收 `{source, sequence, files, currentPath}`；HiViewer v1 插件 API 当前没有 `context.changed` 订阅，也未开放 `host/*` callback，因此不得将官方插件 API 描述为已支持插件向宿主反向切图。

**示例**：

~~~text
HiViewer selection -> native-view viewer/update -> plugin adapter -> LUXE image-sync adapter
LUXE image change -> LUXE image-sync adapter -> plugin adapter -> HiViewer host callback (v1 未提供)
~~~

**违规特征**：插件直接调用不存在的 `api.events.on("selection.changed")` 或 `host/image.select`，或把一次性 `selection.get()` 当作实时事件流。

### R08: 插件双向联动使用独立回传通道

**断言**：需要 HiViewer 操作反向驱动 LUXE 时，插件必须通过获授权的 sidecar 与 LUXE 独立联动适配层通信；推荐优先实现 Windows Named Pipe，插件收到宿主 `viewer/update` 后可展示当前图片，用户在插件内切图时再向 LUXE Named Pipe 发送带版本、来源、序号和绝对路径的消息。

**示例**：

~~~json
{"protocolVersion":1,"sourceInstance":"hiviewer-plugin:<session>","sequence":42,"imagePath":"C:\\tuning\\scene\\IMG_0042.jpg"}
~~~

**违规特征**：把插件 sidecar 的 stdio JSON-RPC 误认为它与 LUXE 已相连，或未实现 LUXE 端接收器却宣称端到端双向同步完成。

### R09: 独立进程优先评估 Windows Named Pipe

**断言**：LUXE Windows x64 与另一个原生进程直接联动时，方案评审必须首先评估 Windows Named Pipe，并比较 localhost TCP/WebSocket 与文件协议；比较项至少包括双向实时性、ACL/认证、断线与重连、消息原子性、端口/路径冲突、用户权限、安装和卸载复杂度、诊断能力与测试成本。

**示例**：

~~~text
Named Pipe: 本机双向流、Windows ACL、无需端口；需实现连接管理和帧协议。
Loopback TCP/WebSocket: 跨语言方便；需随机端口、令牌、绑定回环地址和端口生命周期管理。
文件协议: 部署依赖少；需私有目录、原子写入、轮询/去重，实时性和并发处理较弱。
~~~

**违规特征**：未比较权限与部署成本就选 localhost 监听，或把共享目录中的普通 JSON 文件视为可靠的实时双向消息总线。

### R10: 路径路由进入现有索引状态

**断言**：LUXE 收到消息后使用绝对路径父目录匹配 `useMtkStore.imageDir` 的 workspace `dir`，再以 `ImageEntry.jpg_path` 精确定位条目，并通过统一 store action 设置 `current` 与 workspace selection；未命中必须返回 `image-not-indexed`，不得按文件名猜测。

**示例**：

~~~ts
const key = findWorkspaceKeyByDirectory(dirname(message.imagePath));
const current = useMtkStore.getState().imageDir[key]?.entries.findIndex(
  (entry) => normalizePath(entry.jpg_path) === normalizePath(message.imagePath),
);
if (current === undefined || current < 0) return { accepted: false, reason: "image-not-indexed" };
setWorkspaceImage(key, current, message.imagePath, "remote");
~~~

**违规特征**：直接在组件中更改索引，匹配仅依赖 basename，或找不到路径时自动覆盖其他 workspace 的目录。

### R11: 跨进程消息处理有界且可恢复

**断言**：双向消息必须校验 `protocolVersion`、字段类型、绝对路径、最大消息长度和递增序号；每个 sourceInstance 单独去重，连接断开可重连，关闭/禁用时释放句柄。新增传输实现必须覆盖重复、乱序、断线、未匹配路径和双向回环测试。

**示例**：

~~~rust
if message.protocol_version != 1 || message.sequence <= last_sequence[&message.source_instance] {
    return Err(SyncError::StaleOrUnsupportedMessage);
}
~~~

**违规特征**：无上限读取对端消息、乱序事件覆盖较新选择、重连后创建重复监听器，或只验证消息能发送而未验证反向路径。

### R12: 应用包和插件包分别验收

**断言**：发布变更涉及 LUXE 时必须由 GitHub Actions 生成 Windows x64 安装包并从产物启动验证；涉及 HiViewer 插件时必须运行插件 `check`、`pack`、从包安装启用并验证双向联动。低性能本机不得运行 Rust/Tauri 编译命令；只做类型检查或构建开发目录不算安装验收。

**示例**：

~~~powershell
npm run plugin -- check plugins/luxe-image-sync
npm run plugin -- pack plugins/luxe-image-sync luxe-image-sync-1.0.0.hvp
# Windows x64 安装包由 GitHub Actions 生成后从产物安装验收
~~~

**违规特征**：只有 typecheck/build 结果就声明安装包、插件安装或独立进程双向同步已通过。
