## 规则条目

### R01: 以锁文件为版本依据

**断言**：版本以 `package-lock.json` 和 `Cargo.lock` 为准。新增或升级依赖时同步更新清单和锁文件，并用锁定安装或测试命令验证。

**示例**：

~~~powershell
npm ci
npm run typecheck
cargo fmt --check --manifest-path src-tauri/Cargo.toml
# cargo test --locked --manifest-path src-tauri/Cargo.toml 仅由 GitHub Actions 执行
~~~

**违规特征**：把 package.json 的 ^5.6.3 写成当前 TypeScript 版本，或只改 package.json 而不更新锁文件。

### R02: 沿用当前前端组件体系

**断言**：React 18.3.1 界面优先使用 Fluent UI 9.72.9 和 `@fluentui/react-icons`；共享状态使用 Zustand 5.0.9 和 `src/stores/`。

**示例**：

~~~tsx
import { Button, Switch } from "@fluentui/react-components";
import { Checkmark24Regular } from "@fluentui/react-icons";

<Button icon={<Checkmark24Regular />}>完成</Button>;
~~~

**违规特征**：为普通按钮引入第二套 UI 组件库，或为同一设置创建独立于既有 store 的全局状态容器。

### R03: 同步应用版本

**断言**：正式版本只从 src-tauri/tauri.conf.json 的 version 修改；改动后运行同步与检查命令，提交同步生成的 npm/Cargo 清单和锁文件。

**示例**：

~~~powershell
npm run version:sync
npm run version:check
~~~

**违规特征**：仅修改 package.json 的 version，导致安装包、前端显示和 Rust 包版本不一致。

### R04: 使用当前测试工具链

**断言**：Node 脚本和独立前端逻辑使用 Node.js 22 的 `node:test`；Rust 行为测试使用 Rust 1.95.0 的 `cargo test`，并仅由 GitHub Actions 执行。本地 Rust 修改仅运行不编译的格式与静态检查；新增测试框架前，先更新依赖、锁文件和 CI。

**示例**：

~~~js
import test from "node:test";
import assert from "node:assert/strict";

test("保留原有状态", () => {
  assert.equal(1 + 1, 2);
});
~~~

**违规特征**：新增 Jest 或 Vitest 测试文件却不声明依赖、不接入 CI，或宣称 npm run build 已覆盖桌面端到端交互。

### R05: 锁定五语言国际化契约

**断言**：i18next `23.16.8` 与 react-i18next `15.7.4` 只加载 `zh_CN`、`zh_TW`、`en_US`、`ja_JP`、`tr_TR`；默认及回退语言必须为 `zh_CN`，Node 22 的 `node:test` 或 Rust 1.95.0 的 `cargo test` 必须覆盖列表和资源文件一致性。

**示例**：

~~~ts
export const LANGUAGE_LOCALES = [
  "zh_CN", "zh_TW", "en_US", "ja_JP", "tr_TR",
] as const;
~~~

**违规特征**：重新引入第六个语言代码、通过动态扫描加载白名单之外的语言，或以未声明的测试框架验证语言配置。

### R06: 跨进程传输遵守分层契约

**断言**：跨进程同步的消息类型与路由定义放在 `src/types/` 和 `src/services/`，Tauri invoke/event 仅用于本应用 WebView 与 Rust；Windows x64 原生适配优先评估当前 Rust 工具链可维护的 Named Pipe 实现，不能把 Tauri IPC 当作进程间 IPC。

**示例**：

~~~text
src/types/imageSync.ts          # 传输无关的消息契约
src/services/imageSyncService.ts # 路由、去重和生命周期
src-tauri/src/image_sync/        # Windows 传输适配实现
~~~

**违规特征**：声称两个独立进程可直接共享 Tauri event bus，或在页面组件内创建 TCP/Named Pipe 客户端并自行解析协议。

### R07: 验证使用锁定工具链

**断言**：Windows x64 插件和应用包验证必须使用 Node.js 22、npm 11.12.1、Rust 1.95.0 与锁文件；本地低性能电脑不得执行 Rust/Tauri 编译，插件和应用安装包由 GitHub Actions 生成。插件包执行 CLI `check` 和 `pack` 后必须从包安装，应用安装包从 CI 产物安装并实际启动验收。

**示例**：

~~~powershell
npm ci
npm run plugin -- check plugins/image-sync
npm run plugin -- pack plugins/image-sync image-sync-1.0.0.hvp
# Rust/Tauri 编译和安装包由 GitHub Actions 生成
~~~

**违规特征**：在低性能本机执行 Rust/Tauri 编译，或仅检查开发目录便宣称插件包和 LUXE Windows 安装包已验收。
