## 规则条目

### R01: 以锁文件为版本依据

**断言**：写入依赖版本或选择 API 时，必须核对 package-lock.json 或 Cargo.lock；新增依赖时同步更新清单和锁文件，并用 npm ci 或 Cargo 的 --locked 模式验证。

**示例**：

~~~powershell
npm ci
npm run typecheck
cargo test --locked --manifest-path src-tauri/Cargo.toml
~~~

**违规特征**：把 package.json 的 ^5.6.3 写成当前 TypeScript 版本，或只改 package.json 而不更新锁文件。

### R02: 沿用当前前端组件体系

**断言**：新增 React 18.3.1 界面优先使用 Fluent UI 9.72.9 已有组件和 @fluentui/react-icons；状态共享沿用 Zustand 5.0.9 的 src/stores 实现，不另建平行状态库。

**示例**：

~~~tsx
import { Button, Switch } from "@fluentui/react-components";
import { Checkmark24Regular } from "@fluentui/react-icons";

<Button icon={<Checkmark24Regular />}>完成</Button>;
~~~

**违规特征**：为普通按钮引入第二套 UI 组件库，或为同一设置创建独立于既有 store 的全局状态容器。

### R03: 同步应用版本

**断言**：正式版本只从 src-tauri/tauri.conf.json 的 version 修改；改动后运行同步与检查命令，提交同步生成的 npm/Cargo 清单和锁文件。

**示例**：

~~~powershell
npm run version:sync
npm run version:check
~~~

**违规特征**：仅修改 package.json 的 version，导致安装包、前端显示和 Rust 包版本不一致。

### R04: 使用当前测试工具链

**断言**：Node 脚本及可独立测试的前端逻辑使用 Node.js 22 内置 node:test；Rust 行为使用 Rust 1.95.0 的 cargo test。新增前端组件测试框架或桌面端到端框架前，必须先更新 package.json、锁文件与 CI；不得把未安装的框架写成现有能力。

**示例**：

~~~js
import test from "node:test";
import assert from "node:assert/strict";

test("保留原有状态", () => {
  assert.equal(1 + 1, 2);
});
~~~

**违规特征**：新增 Jest 或 Vitest 测试文件却不声明依赖、不接入 CI，或宣称 npm run build 已覆盖桌面端到端交互。
